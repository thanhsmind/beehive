# rust-port-17 — bee-chain-nudge + bee-state-sync hooks incl. worktree-holds renewal, conformance

**Status:** [DONE]

**Outcome:** Ported the two remaining heavy hooks onto the rust-port-7 hook runtime — `bee-chain-nudge` (`crates/queen-bee/src/hooks/chain_nudge.rs`, read-only SubagentStop advisory: worker-collect nudge, review-synthesis nudge, scribing-debt warning) and `bee-state-sync` (`crates/queen-bee/src/hooks/state_sync.rs`, silent throttled heartbeat + reservation-lease + cross-worktree-hold renewal, then the locked `rebuildStateProjection` call from rust-port-16 with LOCK_BUSY skipping silently). Backing write paths were added to `bee-core` since they didn't exist yet: `claims::heartbeat_session`/`renew_claim_ttl` (the one write path `heartbeatTouch` composes), `reservations::renew_holds_by_session` (the one lease-store write path the hook needs), and `holds::renew_holds` (the cross-worktree-holds renewal path, added to the previously read-only `holds.rs`). The new `heavyhooks_conformance` target (`crates/queen-bee/tests/heavyhooks_conformance.rs`, 16 tests) proves byte-identical advisory JSON / silence for chain-nudge across trigger and silence classes, and side-effect parity for state-sync (state.json rebuild, heartbeat/claim/lease/hold renewal, throttle no-op, LOCK_BUSY skip, crash fail-open) against the real frozen mjs oracles on seeded fixture roots — fixtures seeded via a new tracked driver, `tests/support/heavyhooks_fixture.mjs`, which builds authentic session/claim/lease/hold records through the real `claims.mjs`/`lease-store.mjs`/`worktree-holds.mjs` functions rather than hand-guessed shapes.

**Deviations (disclosed):** (1) only the one write path each hook's call site exercises was ported from claims.mjs/reservations.mjs+lease-store.mjs/worktree-holds.mjs — every other mutating function in those modules (adopt/release/sweep, epoch fencing, lease acquire/release, mirror/release/sweep) stays unported, out of scope. (2) a real byte-compatibility bug was caught by this cell's own oracle diff during development and fixed before capping: the first `heartbeat_session`/`renew_claim_ttl` draft round-tripped through bee-core's typed `Session`/`Claim` structs, which serialize `Option` fields as `null` when absent — the mjs source's own plain-object writes never introduce a key the file didn't already have. Fixed by patching the raw `serde_json::Value` in place for both writes. (3) `chain_nudge.rs` uses the hook's own bare root everywhere (matching bee-chain-nudge.mjs's literal usage, which never references `ctx.controlRoot`); `state_sync.rs` mirrors bee-state-sync.mjs's mixed usage (heartbeat/hold-renewal take the control root, lease-renewal/rebuild take the bare root, each per the mjs source's own literal call).

## Rework round (goal-check judge: NEEDS_REVISION, fixability automatic)

An independent goal-check judge verified the cell hard (rig sha256-checks, non-triviality assertions, LOCK_BUSY via a real background-thread holder, genuine crash panics — all confirmed real) and returned four findings, all fixed with red-first proof (bug reintroduced, test run to failure, reverted, re-run green):

1. **Crash-log hook-name divergence (real behavior bug).** `run_fail_open` (`write_guard.rs`) hardcoded `adapter::log_crash`'s hook-name argument to this file's own `HOOK_NAME` constant, so a chain-nudge or state-sync panic logged `"hook":"write-guard"` instead of the real crashing hook's name — invisible because the crash tests only asserted an `error` substring, never compared the two runtimes' log lines. Fixed by threading `hook_name: &str` through `run_fail_open` and updating every caller (`write_guard`, `model_guard`, `chain_nudge`, `state_sync`) plus the 4 pre-existing direct-call test sites that previously passed no hook name at all (`writeguard_core.rs`, `writeguard_read.rs`, `writeguard_bash.rs`, `modelguard_conformance.rs` — the last of these was itself silently asserting the wrong hook name for a model-guard crash test). The two crash tests were merged into `chain_nudge_crash_fail_open_both_runtimes_log_the_correct_hook_name` / `state_sync_crash_fail_open_both_runtimes_log_the_correct_hook_name`, each now asserting `hook`-field equality cross-runtime. Red quote: `assertion left == right failed: rust port crash line hook field ... left: Some(String("write-guard")) right: Some(String("chain-nudge"))`.
2. **Authoritative state-projection rebuild was never proved.** No fixture seeded a workflow record, so every state-sync fixture landed in `rebuild_state_projection`'s `apply_overrides_only` fall-through — the branch the hook exists to route through was never diffed against node, and the old test's name (`state_sync_idle_bootstrap_rebuild_matches_oracle`) overclaimed a branch it never constructed. Fixed by adding a real `workflow` fixture op (`heavyhooks_fixture.mjs`, via the real `workflow-store.mjs` `createWorkflow`) and a new test, `state_sync_authoritative_idle_bootstrap_adopts_active_workflow_matches_oracle`, asserting phase/feature/mode/summary/next_action/approved_gates are adopted from a seeded active workflow, cross-runtime, byte-level; the old test was renamed to `state_sync_no_workflow_records_only_refreshes_overrides_matches_oracle` with an explicit "phase stays idle" assertion proving it is the fall-through. Red quote (workflow seeding commented out): `assertion left == right failed: node: phase must be adopted from the active workflow left: Some(String("idle")) right: Some(String("executing"))`.
3. **The hold row had no cross-runtime comparison at all** — session, claim, and lease each had one; the hold ledger (`holds.rs`'s typed `Hold` round-trip, the same shape of bug the session write path was fixed for) was guarded only by prose. Fixed by adding a hold-ledger comparison to the renewal test.
4. **Store-file comparisons used parsed `serde_json::Value`s**, which under this workspace's `preserve_order` feature are backed by an `IndexMap` whose `PartialEq` ignores key order — invisible to every prior file comparison in this suite (the same class rust-port-15's rework separately found two real instances of). Fixed by adding `assert_files_byte_equal_redacted` (redacts a field's value directly in the raw file text, then compares bytes) and converting every store-file comparison (state.json, session.json, claim.json, lease file, hold ledger) to it, plus a permanent meta-test, `byte_level_comparison_catches_key_order_divergence_that_value_equality_misses`, proving the blind spot is real and the fix closes it. Red quote (finding 3+4 combined — `Hold`'s `feature`/`session` field order temporarily swapped): `assertion left == right failed: state-sync/renewal cross-worktree-holds.json: byte-level (key-order-sensitive) file comparison diverged left: ..."feature": null,\n      "session": "sess-stale"... right: ..."session": "sess-stale",\n      "feature": null...`.

`heavyhooks_conformance.rs` stays at 16 tests (2 crash tests merged into 2 stronger ones; 2 new tests added: the authoritative-rebuild test and the byte-level meta-proof). Re-verified green: `cargo test -p queen-bee --test heavyhooks_conformance` (16 passed), `cargo test -p bee-core` (172 passed), `cargo test -p queen-bee` (117 passed), `cargo build --workspace` clean. Judge override recorded (a worker cannot dispatch a fresh judge pass, per AO14; the coordinator instructed capping after this rework) — full trace in `.bee/cells/rust-port-17.json`.
