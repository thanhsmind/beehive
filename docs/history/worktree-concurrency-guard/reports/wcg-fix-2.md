# wcg-fix-2 — shared-checkout detection fails CLOSED (not open) on a detection error

**Status:** [DONE]

**Outcome:** Fixes review finding #2 (P1, `worktree-concurrency-guard-review-20260724`). `plan.md`'s Test Matrix requires the "failure mode of the check itself" — a corrupt marker, broken symlink, or unreadable nested `.git` — to fail CLOSED on the concurrency+shared-target question, "never silently allow because detection itself errored." But the write-guard hook's dispatch called `guards.isSharedNestedCheckoutTarget(...)` unguarded, so a thrown detection error propagated to the hook's outer catch-all (`return 0`) and failed OPEN — most likely exactly during a real race. Fix: wrap ONLY that call site in its own `try/catch` so a genuine thrown exception produces a typed deny (`sharedNestedDetectionErrorRefusal`), distinct from the hook's general-purpose fail-open catch-all, which stays fail-open by design for unrelated checks. `hasGitNode` / `findNestedCheckoutDir`'s internal continue/false-on-nonexistent-path behavior is untouched — a path that does not exist is a legitimate "nothing there" answer, not a detection error.
