# Delivery — per-task-router

Feature: the leader routes the task in hand, and every code cell is built by one worker and certified by a separate tester. Rules are CONTEXT.md D1-D5; planning choices are decision `58d7b2a7`.

## Concepts changed

- `docs/knowledge/areas/doctrine-layer/per-task-route-tester-pairing-and-proof-floors.md`: new concept for the per-task route, the preamble hint, the tester pairing and its close and merge refusal, the worker Principles block with its holdout, the cap's principle answer and the proof floors (D1-D5), because no existing concept owned them and the router concept is already past 300 lines.

## What shipped

- The preamble prints Route and principles only for a route the session owns; `bee orient --class <c>` routes the task in hand (D4).
- `bee dispatch prepare` hands every worker its class Principles block with a holdout (D5.3).
- The cap names applied principles and refuses a proof weaker than its floor, with `green:red-first` added (D5.4, D5.5).
- `bee cells add` stamps and warns; close and merge refuse a stamped code cell with no capped tester; an inline code cap is refused (D1-D3).
- `LEADER.md`, planning, swarming and the playbooks teach the per-task route, the trigger index and the two-worker rule (D5.1, D5.2).

## Known limits

- Cells added before the stamp are exempt from the pairing refusal.
- The holdout arm and older prepare records can cap without a principle answer.
- The cell-6c verify filter named `parity` skips the parity test files; rule index parity and pointer integrity were run by name and passed on 601a09246. The release manifest check was not run.
- The generated knowledge indexes were not regenerated by `bee knowledge index` in this round; the doctrine-layer index line was added by hand.
- The slice-tail consolidated test cell question (specs #80, #85) and the pstack refresh stay open.
