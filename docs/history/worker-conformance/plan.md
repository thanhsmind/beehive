# Plan: Worker Conformance And Evidence Diet

Mode: `high-risk` — 3 risk flags: public contracts (`bee.mjs cells cap` refusal
surface), multi-domain (execution + planning doctrine), **validation removal**
(D1 deletes two refusal doors — a hard-gate flag on its own).

Why this is the least workflow that protects the work: the feature's whole
subject is deleting proof requirements, which is exactly the class the hard gate
exists for; the epic map below is three slices, and slice 1 exists only because
removing the doors without it is unsafe.

## Requirements (from CONTEXT.md)

- **D1** — exactly two throws become non-blocking recorded facts: the
  `behavior_change`-without-evidence door (`cells.mjs:1956-1960`) and decision
  0004's "an assertion is not evidence" door (`cells.mjs:2164-2168`). The
  non-empty `files_changed` door (`cells.mjs:2169-2173`) stays refusing.
- **D2** — red-first is untouched: `security`/`migration` (all lanes) and lane
  `high-risk` (all classes) still refuse without `red_failure_evidence`.
- **D3** — feature-boundary proof stays the sole blocking proof; main-verifies'
  close-door is not relaxed; `commands.test` stays impacted-only.
- **D4** — the trailing test cell stays unconditional, but its first mandated
  step is a coverage judgment; "already covered, no new rows" is a legal cap.
- **D5** — triad (happy path / edge cases / error paths) is the shape at lane
  `standard` and below; `edge-dimensions.md` applies only at `high-risk`.
- **D6** — no numeric per-group cap; ratio ceiling, `new_suite_reason`, and the
  refactor+new-test-file refusal are untouched.
- **D7** — every loosening ships in the same cell as a table-driven negative
  control proving the heavier tiers still refuse.
- **D8** — the worker's pre-code conformance checklist (a) and three post-edit
  checks (b) ride along; (c) is D4.
- **D10** — a cap with no real recorded verify output is auto-marked unproven;
  an asserted `--passed true` with empty output is never proof.
- **D11** — `featureVerifyDebt` and `testCellDebt` inherit the same treatment.
- **D12** (refines D10, decided in this plan's review wave) — the marker is a
  **new** field `trace.proof = "unrecorded"`, never a reuse of
  `trace.feature_verify = "pending"`. `pendingFeatureVerify` short-circuits five
  refusal doors (`cells.mjs:1886-1899`, `:1912`, `:1999`, `:2032`, `:2135`,
  `:2164`); reusing it would have gutted D2's red-first tier and D6's brakes the
  moment slice 1 landed. `"unrecorded"` arms the close-door and buys no bypass.
  Repos with `commands.verify === "none"` are exempt from auto-marking. Debt
  freshness runs over the **union** of `pending` and `unrecorded` caps.
- **D14** (advisor consult) — a cap is `"unrecorded"` only when neither real
  verify output **nor** `verification_evidence` was supplied.
- **D13** (decided in this plan's review wave) — this feature ships one trailing
  `change_class: 'test'` cell despite the high-risk per-cell doctrine, because
  `testCellDebt` (`state.mjs:2606`) has no lane exemption and would refuse the
  feature's close with zero test cells. The doctrine-vs-machine gap
  (`skills/bee-planning/SKILL.md:76` permits what the machine refuses) is
  recorded as a finding for compounding, not fixed here.

D9 needs no cell: it is CONTEXT.md's traceability record of the autopilot
approval, not a behavior.

## Discovery

L1. Inspected: `packages/bee/lib/cells.mjs` (`capCell` refusal chain, verified
line-by-line by the fresh-eyes reviewer), `packages/bee/lib/state.mjs:2502-2570`
(`featureVerifyDebt` / `testCellDebt`), `packages/bee/tests/test_cells.mjs`
(refusal-branch coverage), `packages/bee/tests/test_bee_cli.mjs:2596+` (the
door × debt-kind matrix), `scripts/render_plugin_skill_trees.mjs`.

Findings that shaped the plan:

1. `requiredProofTier` is consumed at only two call sites (`cells.mjs:2103`,
   `:2135`), both `'red-first'`. The `targeted-green` / `existing-targeted-green`
   / `suite-green` tiers have **no** cap-time enforcement of their own — the two
   doors D1 removes were the only thing forcing recorded output on non-red-first
   cells. This is why slice 1 must land before slice 2.
2. `recordVerify` (`cells.mjs:1747-1756`) validates only `command` and `passed`;
   `output = null` is legal today.
3. The two skills exist at **five** paths each (canonical `skills/`, plus
   `.claude/skills/`, `.agents/skills/`, `.claude-plugin/skills/`,
   `.codex-plugin/skills/`). The plugin trees are regenerated by
   `node scripts/render_plugin_skill_trees.mjs`; `.claude/skills/` and
   `.agents/skills/` are written by `packages/bee/scripts/onboard_bee.mjs`.
   A text edit therefore owes a projection step, not four hand-copies.
4. An existing table-driven negative-control pair to copy:
   `packages/bee/tests/test_cells.mjs:2189-2239` (widened-pass at `:2189`,
   still-refused at `:2212`), same fixture pipeline, differing only in
   `assert(capped.status === 'capped')` vs `assertRejects(..., needle)`.

5. `pendingFeatureVerify` is not a neutral marker: it short-circuits the
   passing-verify requirement (`cells.mjs:1912`), the `new_suite_reason` door
   (`:1999`), the ratio refusal (`:2032`, downgraded to a warning), the
   red-first `red_failure_evidence` door (`:2135`), and decision 0004 (`:2164`);
   `:1886-1899` also refuses combining it with a recorded passing verify. Hence
   D12's separate field.
6. `testCellDebt` (`state.mjs:2606`) refuses a feature close when capped
   code-touching `behavior`/`api` cells exist and no `test` cell does — no lane
   exemption, no bypass. Hence D13.

Evidence command: `node packages/bee/tests/test_cells.mjs` — run the suite
unfiltered. `BEE_CHECK_ONLY=capCell` is **red by construction** here (7 passed,
35 failed): the filter skips the shared fixture-setup checks the cap tests
depend on.

## Approach

Recommended path: **arm the net before cutting the rope, with a marker that arms
nothing else.** Slice 1 introduces `trace.proof = "unrecorded"` (D12) and teaches
both close-door predicates to arm on it (D11), so absence of proof becomes
blocking at the feature boundary while every per-cell door keeps its current
force. Only then does slice 2 make the two per-cell doors non-blocking (D1),
carrying its negative control in the same cell (D7), and close the feature's own
test debt (D13). Slice 3 is instruction text plus the projection step
(D4, D5, D8).

Rejected alternatives:

- *Reuse `trace.feature_verify = "pending"` as the absence marker.* Rejected —
  the review wave's blocker: it short-circuits five refusal doors including
  red-first (`cells.mjs:2135`) and the ratio ceiling (`:2032`), so slice 1 alone
  would have voided D2 and D6 before slice 2's negative controls existed.
- *Relax `cells.mjs:1895-1899` (pending + recorded passing verify) instead.*
  Rejected: reaches the same bypass by another path.
- *Drop the doors first, add the marker later.* Rejected: between the two slices
  the repo can close a feature with zero tests executed anywhere
  (`state.mjs:2502-2518` returns `null` when no capped cell is pending).
- *Make `--feature-verify-pending` mandatory by instruction only.* Rejected:
  instruction prose is not a mechanism.
- *Also drop red-first (the fully-flat option).* Rejected by D2 — red evidence is
  build-emitted, so it is not the thing that causes drift.
- *Follow the high-risk "no trailing test cell" doctrine literally.* Rejected by
  D13: `testCellDebt` would refuse the feature's close and no bypass lifts it.
- *Merge the two instruction-text cells into one.* Rejected on concurrency, not
  cost: they touch disjoint paths and run in the same wave.

Risk map:

|---|---|---|
| `capCell` unproven marker (D10/D12) | **HIGH** — mislands and every cell caps unproven, or buys a door bypass | red-first: an output-less pass must set `trace.proof === "unrecorded"` **and** must still hit red-first / ratio / `new_suite_reason` where those applied before |
| `featureVerifyDebt` / `testCellDebt` (D11) | **HIGH** — the door is the only remaining blocking proof | red-first at the CLI door × debt-kind matrix, both kinds, on the new marker |
| Two doors non-blocking (D1) | **HIGH** — this is the validation removal | red-first + D7 negative control in the same cell |
| Instruction text (D4/D5/D8) | LOW | text; projection byte-identity is the only mechanical claim |
| Projection to 5 trees | MEDIUM — a stale copy ships the old law | `node scripts/render_plugin_skill_trees.mjs` then the repo's own render/pointer tests |

## Test matrix

High-risk depth — probes written out per applicable dimension:

- **State transitions** — cap with real output → `trace.proof` unset; cap with
  `--passed true` and empty output → `trace.proof === "unrecorded"` (D10/D12);
  cap with `--feature-verify-pending` explicitly → `trace.feature_verify ===
  "pending"`, unchanged, and `trace.proof` untouched.
- **Data integrity (D12's whole point)** — `"unrecorded"` must buy **no** door
  bypass: an `"unrecorded"` cell that is `security`/`migration` or lane
  `high-risk` still refuses without `red_failure_evidence` (`cells.mjs:2135`);
  still refuses a new test file without `new_suite_reason` (`:1999`); still
  refuses over the ratio ceiling at `standard`+ (`:2032`). Each is its own row.
- **Data integrity** — a repo with `commands.verify === "none"` (the
  `noTestWaiver` path, `cells.mjs:1908`) is never auto-marked, since its
  close-door could otherwise never be satisfied.
- **Authorization / bypass** — `gate_bypass_level: total` still cannot pass the
  close-door with a pending cell (existing `test_bee_cli.mjs:2575` must stay
  green).
- **Error cascades** — `featureVerifyDebt` (`state.mjs:2502-2518`) and
  `testCellDebt` (`state.mjs:2546-2570`) both refuse on an output-less asserted
  pass; the door × debt-kind matrix (`test_bee_cli.mjs:2699-2719`) covers every
  registered door, and the coverage-completeness meta-check
  (`test_bee_cli.mjs:2670`) means a new debt kind owes a fixture.
- **Business logic (negative control, D7)** — table-driven pair: `behavior_change`
  and small-lane cells now cap without evidence, **and** `security`/`migration`
  any lane, `high-risk` any class, still refuse without `red_failure_evidence`;
  `refactor` + new test file still refused with no override; ratio ceiling and
  `new_suite_reason` still refuse.
- **Input extremes** — `output: ""`, `output: "   "`, `output: null`, `output`
  absent all read as "no proof recorded"; a one-line real output does not.
- **Data integrity (D14)** — a cell with empty `verify_output` but supplied
  `verification_evidence` is **not** marked: the tiny-lane `security` cell whose
  80-char `red_failure_evidence` already passed `cells.mjs:2135` holds the
  strongest proof in the system and must not arm the close-door.
- **Timing / staleness (D12)** — `featureVerifyDebt`'s freshness comparison
  (`state.mjs:2506-2523`, `newestPendingCapMs`) runs over the **union** of
  `pending` and `unrecorded` caps: a green feature-verify record newer than the
  newest `pending` cap but older than a newer `unrecorded` cap must still refuse.
- **State transitions (implementation constraint)** — the marker is stamped
  after the whole refusal chain has run (post-`cells.mjs:2178`); a cell that the
  chain refuses is never stamped, and `feature_verify_pending` is never set
  internally to reach it.
- **Integration** — all five skill trees byte-identical after the projection step.

### Accepted residual risk (named, not solved)

After this feature, a determined worker can still close a feature green with no
test ever executed, by two pre-existing paths this feature neither opens nor
closes. Both are stated here so the record is honest about what D10/D12 buy:

1. **Fabricated per-cell output.** `recordVerify` (`cells.mjs:1747-1756`)
   validates only `command` and `passed`; `--passed true --output "all green"`
   with nothing run yields non-empty output, so the marker never fires. D10/D12
   catch *laziness* (absent proof), not *deception* (invented proof).
2. **Fabricated feature-verify record.** `feature-verify record`
   (`.bee/bin/bee.mjs:4504-4512`) only checks that `--output-file` is readable
   and stores its sha256; content is never validated, so one fabricated file
   clears the close-door for every `unrecorded` cap.

Closing either is a different feature — it needs proof the worker cannot author,
which is the same root as the deferred `change_class` self-declaration idea.

Answered, no longer deferred: the `no-test repo` sentinel
(`commands.verify: "none"`) is **exempt** from D10/D12 auto-marking — the
`noTestWaiver` path (`cells.mjs:1908`) has no verify output by construction, so
auto-marking would arm a close-door such a repo could never satisfy. That
exemption is a required test row, not a note.
