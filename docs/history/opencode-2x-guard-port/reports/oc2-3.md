## Red-green

The 2.x `setup` hook has no `throw` statement of its own. Its block path is the throw that `runBlockingHook` raises and `guardToolCall` passes up. To remove the throw from the 2.x hook only, I made the hook swallow it. The 1.x path stayed unchanged:

```
-    guardToolCall(directory, call.sessionID, TOOL_ID_2X[call.tool] ?? call.tool, args, { args: input })
+    try { guardToolCall(directory, call.sessionID, TOOL_ID_2X[call.tool] ?? call.tool, args, { args: input }) } catch {}
```
