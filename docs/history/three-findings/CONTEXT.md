# three-findings — context

## What this is

The three findings the pi-capability-audit lane filed and did not fix, taken
together because each is small and they share no files.

1. `gather.md`, `reviewer.md` and `advisor.md` declare a `{{#if paths}}` block
   that nothing supplies.
2. The codex capability-probe concept points at a constant and a script that
   no longer exist.
3. `bee herding run --help` omits `--seat` and `--inbox-session`.

## Locked decisions

**D1 — the `paths` block is deleted, not wired.**
It has a discoverable origin and no reason to stay. Commit `58be9dfec`
(2026-09-07, "Retire dated prompt patterns and dead names from the instruction
surface") replaced a literal placeholder line — `Paths: <caller fills in the
exact files/paths to read>` — with a conditional block, so that placeholder
prose would stop reaching workers. It never wired a supplier, and the
follow-up commit `bc232b8fe` re-cut the test goldens to match the new,
always-empty output. The carrier that did arrive for this job is
`--brief-file` (slp-blind-lanes). Deleting the block removes dead surface and
changes zero rendered bytes, because an absent var is falsy and a falsy block
leaves no residue.

**D2 — the codex concept's dead pointers are corrected, its live one is kept.**
`PROBED_CODEX_VERSION` and `scripts/canary_codex.mjs` do not exist at this
commit, and neither does `.bee/cells/i54-closeout-8.json`.
`docs/history/i54-closeout/reports/validation-canary.md` does exist and stays.
The mechanism that survived the Rust port is the attestation record.

**D3 — the two herding flags are added to the command registry, and the
pinned flag count is bumped on purpose.**
`registry_payload.json` is the only home for flag help text; no `bee dev` verb
regenerates it, so it is edited directly. Neither `seat` nor `inbox-session`
exists anywhere in the registry today, so both are genuinely new spellings and
the distinct-flag count moves 208 to 210 with its reason recorded in the
`catalog.rs` ledger, exactly as that ledger's own discipline requires.

**D4 — one stale sentence outside the three findings is fixed with D1.**
`docs/product-description/delegation/dispatch.md:47` still describes the old
literal behavior ("its own task text filled into the prompt's `Paths:` line").
It has been wrong since `58be9dfec` and it describes the very surface D1
deletes, so it moves in the same cell rather than being filed again.

## What is NOT in scope

- Wiring a `paths` supplier. Nobody asked for the feature and `--brief-file`
  already carries the job.
- The `registry.rs` header comment calling the payload "generated by `bee
  dev`" when no such verb exists. Noticed while tracing D3; filed, not fixed.

## Evidence base

- `git log -S'{{#if paths}}'` over the three templates, and the two commits
  named in D1.
- `rg '"paths"'` over `packages/bee-rs` — no supplier in any source or test.
- `devtools/release_manifest.rs:74-88` — `packages/bee` is an inventory root,
  `packages/bee-rs` is not, so only the prompts cell owes a manifest refresh.
- `PINNED_FLAG_COUNT = 208` at `catalog.rs:788`, and a count of the live
  payload that returns exactly 208.
