## Convergent findings (3+ hats agree)

1. **"Every human request" is the wrong trigger.** All five hats.
   A clear/tiny ask hitting a five-seat wave is the ceremony-capture
   failure the repo already names (gates-and-delegation.md:191;
   bee-shaping SKILL triage table). The trigger must be a *feature
   intake entering shaping*, once per feature — never per message
   (AGENTS.md "A question is a question"; D6 pure-question boundary).
2. **Hats at intake are generation, not critique — D7 collision.**
   facts-gaps, risks, alternatives. slp-blind-lanes D7 defines hats as
   critique of ONE existing draft (gates-and-delegation.md:181). With
   no draft, five seats generate product intent with none of the lane
   protections. Shaping must define the hats' input (raw request +
   leader restatement?) and pin their altitude to question-generation.
3. **Wave output enters ONLY through the interview.** risks,
   user-impact, facts-gaps, alternatives. Lock renders, never
   originates; a wave-derived CONTEXT.md line must cite the human's
   answer to a wave-derived question, never the hat output itself.
   One merged question set from the leader, obeying the 2–4 question
   materiality cap — never five voices.
4. **Keep the pre-Lock wave (absorb, do not retire).** risks #8,
   alternatives shape 2, facts-gaps #7. The pre-Lock window is the only
   channel where a product finding reaches the finished draft; intake
   hats cannot critique a draft that does not exist yet. Two windows,
   two jobs: intake = framing, pre-Lock = critique (discretionary, as
   today).
5. **Headless/Qualify/bypass has no consumer.** risks #5-6, facts-gaps
   #5/#9, user-impact #8. Wave questions cannot block an unattended
   run: Explore-only, or headless output collapses into Outstanding
   Questions.
