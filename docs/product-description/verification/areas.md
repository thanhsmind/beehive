# Verification: areas

How to run this file: build or use the vendored binary (`.bee/bin/bee`) at the pinned commit, and keep the linked document open beside the terminal. Most rows are read-only runs — the Needs column says `—` for those, meaning any onboarded checkout will do; `beehive` means this repository's own store (its decisions, maps, lanes and cells are the fixture). Store-writing rows say `scratch`: make a throwaway host repo (`mkdir -p host/.bee && echo '{}' > host/.bee/onboarding.json`), run from inside it, delete it afterwards — no hooks fire there, so the binary's own behavior is isolated and a fixture file may be placed by hand. `hooked` needs a live Claude Code session with bee's hooks wired (the only way to see denies, repairs, the preamble); `worktree` needs a granted feature worktree plus main; `two sessions` needs two live hooked sessions in one checkout; `piped` means the run is repeated with `1>/dev/null` and `2>/dev/null` to check the stream split; `codex` rows are expected `blocked` until a Codex host exists. Record `pass`, `fail`, or `blocked` in the Result column with a short note for anything but a clean pass.
