# Verification: cross-cutting

How to run this file: most rows here need a **scratch** host repo — `mkdir -p host/.bee && echo '{}' > host/.bee/onboarding.json && git -C host init` — with no `.bee/config.json` and no `.bee/config.local.json` unless a row seeds them, run with `.bee/bin/bee` from the beehive checkout at the pinned commit. Delete `host/` between sections; a leftover config file is the most common cause of a false fail in the CONF table. Rows marked **hooked** need a live session under Claude Code with bee's hooks wired in a disposable clone, because a deny, a repair, a fail-open line, and the privacy marker exist only in the tool-call channel. **piped** means stdout and stderr are separated (`>/dev/null` for one, `2>/dev/null` for the other) so the stream split can be read. **worktree** means a granted feature worktree plus main; **two sessions** means two live hooked sessions in one checkout; **codex** rows are expected `blocked` until a Codex runtime exists. Set `gate_bypass` back to absent and delete every hook toggle before leaving a section — a `hooks.write-guard: false` left behind silences every later row in the PRIV and FAIL tables.
