# Codebase Overview

bee is a gated agent workflow harness: a single native CLI plus a set of skills
and lifecycle hooks that hold an agent to explore → gate → plan → execute →
scribe → compound, with four human gates and evidence required at every cap.
It ships as a Claude Code / Codex plugin, installs itself into a host repo
(`bee onboard --apply`), and keeps that repo's runtime state under `.bee/`.

**Currency.** This file is orientation for a cold reader — where code lives and
what conventions hold. It is a map of the tree as it stands after the R6 Node
cutover (2026-08-01): there is no second runtime, and no `.mjs` runtime code
remains outside `packages/bee/scripts/plugin_distribution.mjs`. Re-derive it
against the tree rather than trusting it after a structural change; a wrong
fact here is worse than an omission. Design intent and history live in
`docs/02-architecture.md`; behavior lives in `docs/knowledge/`; this file holds
neither.

## Entry points

- `packages/bee-rs/crates/bee/src/main.rs` — the whole CLI: collect argv, hand
  it to `router::try_native`, exit.
- `…/src/router.rs` — the probe chain. Each verb exposes
  `try_native(args, t0) -> Option<ExitCode>` and serves **only** the argv shapes
  its port proved. `None` from every probe is the end of the line:
  `emit_unsupported_shape` refuses out loud with a non-zero exit. Nothing falls
  through to anything.
- `…/src/verbs/mod.rs` — the probe order, one line per verb group.
- `.bee/bin/bee.exe` — the vendored binary a host repo actually runs.

## Key conventions

- **Rust 2024**, `anyhow` for error propagation. No CLI parsing framework — each
  verb matches its own argv shapes, which is what makes the probe contract
  possible.
- **Refuse out loud, never fall silent.** An unclaimed argv shape, a failed
  guard, a denied reservation: each produces a named refusal and a non-zero
  exit. Silence is the defect.
- **Byte-compatible persistence.** On-disk stores were written by the retired
  Node runtime, so `serde_json` runs with `preserve_order` and writes through
  `jsjson.rs`; lock files, holder bodies, and the manifest hash stay
  byte-identical to what Node produced.
- **Provenance comments.** Ported modules name their `.mjs` source and the
  contract they preserve at the top of the file. The header is where a reader
  learns *why* a rule exists — read it before the code.
- **State is CLI-owned.** Every mutation of `.bee/*.json(l)` goes through a verb;
  the write-guard hook denies direct edits. Skills reference `.bee/expertise/…`,
  never the source `expertise/`.
- **Generated artifacts carry a `--check`.** The knowledge index, the release
  manifest, and the embedded registry payload each regenerate deterministically
  and fail loudly when stale — no hand-maintained mirror lists.
- **Tests colocate.** ~906 `#[test]` functions live in 60 `mod tests` blocks
  beside the code they cover; cross-cutting suites live in `tests/`.

## Build and test

```bash
cargo test --release --manifest-path packages/bee-rs/Cargo.toml
```

That exact command is what `.bee/config.json` records as `commands.test`, so
`bee test` and the `bee cells finish` / `bee close` doors all run it. Green caps
the work; red refuses the cap and becomes the next piece of work.

Integration suites under `packages/bee-rs/crates/bee/tests/`:

| Suite | Covers |
|---|---|
| `instruction_laws.rs` | The instruction layer says what the code does |
| `concurrency.rs` | Locks, leases, and parallel-session contention |
| `hook_contracts.rs` | Each hook's input/output contract |
| `registry_contracts.rs` | The embedded registry payload matches the live surface |
| `front_door.rs` | Routing, refusals, and payload freshness |
