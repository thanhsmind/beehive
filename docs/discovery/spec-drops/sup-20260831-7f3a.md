This spec is the bee-side portion.

What already exists (checked against beehive main @ 681ddc52, bee 2.30.0):

- `bee supervisor` has all 10 verbs: record / list / pending /
  mark-delivered / away / back / presence / report / metrics /
  consent-sweep.
- Frequency cap, mailbox, presence window, the 4-item WakeReport, the
  7-metric two-sided health report, and fail-closed silence-is-consent are

- `skills/bee-herding/references/supervisor-prompt.md` already exists, with
  a clear observer contract ("You never dispatch work", cold tick, no
  memory carried between ticks).
- `.bee/config.json` declares the `supervisor` role as `haiku`.

Four gaps that need the receiving repo's own triage:

1. **The mailbox is write-only.** `rg "supervisor pending"` across all of
   beehive only hits the source CLI (`verbs/supervisor.rs`, `catalog.rs`,
   `registry_payload.json`) and `docs/history/slp-advisor-nudge/plan.md` —
   **no hook, no skill reads `bee supervisor pending` at a turn boundary.**
   Yet `record`'s own help text says a row "is read by the target session
   at its next turn boundary." If nothing reads it, an intervention or
   escalation written to the mailbox never reaches anyone.

2. **Does the control loop accept `--role supervisor` yet?** bee 2.29.0
   (the version waggledance currently vendors) has
   `herding control-loop --role*` accepting only `dispatch or merge`. But
   `supervisor-prompt.md` already sits in
   `skills/bee-herding/references/`, exactly where the loop looks up a
   role's prompt. Verify on 2.30.0; wire it if it is not wired yet.

3. **Cross-project visibility.** `.bee/supervisor/` anchors at the control
   root — i.e. **per-repo**, not cross-repo. Demonthorn §9 says the role's
   core value is seeing across multiple workflows. The distill's proposal:
   **keep the store per-repo** (it correctly enforces the §9 constraint of
   "never use project A's evidence to accept project B"), but bee needs a
   **documented contract for a tick triggered from outside** — waggledance
   will be the caller. Deciding that contract's shape belongs to this
   repo's own triage.

4. **Notebook shape.** §4.2 requires the output to carry Observation /
   Evidence / Suspected mechanism / Impact / Question / Recommendation /
   Escalation, and stresses the notebook must store **causal context, not
   just a verdict** ("storing only the verdict teaches the system to learn
   a slogan"). `record --note` is currently free text. Check whether
   `supervisor-prompt.md` already enforces this shape; if it does, close
   this item — don't add redundant validation.
